The names given to @pytest.mark.parametrize must match the test's parameters, and each row must have one value per name.

Why is this an issue?

A row of the wrong length makes pytest error at collection; a misspelled name errors or feeds a different fixture than intended. Only literal names and literal rows (tuples, lists, pytest.param(...)) are checked. A name missing from the signature is reported only when it is a near typo of a parameter, or when the test takes no parameters and the file has no autouse or usefixtures fixture, since a parametrized name may legally feed a fixture. Indirect parametrization and tests taking *args / **kwargs are not checked for names.

Noncompliant code example

@pytest.mark.parametrize("a,b", [(1, 2), (2,)])  # Noncompliant
def test_pairs(a, b):
    assert a < b

@pytest.mark.parametrize("expected", [1, 2])  # Noncompliant
def test_value(expect):
    assert expect

Compliant solution

@pytest.mark.parametrize("a,b", [(1, 2), (2, 3)])
def test_pairs(a, b):
    assert a < b

@pytest.mark.parametrize("expected", [1, 2])
def test_value(expected):
    assert expected
