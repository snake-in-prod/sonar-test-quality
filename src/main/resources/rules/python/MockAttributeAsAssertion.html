An assert on a mock's assertion method without calling it (assert m.assert_called_once), or on an attribute the mock creates on access (assert m.called_with), tests a bound method or a child mock.

Why is this an issue?

Both are always truthy, so the assertion never fails and the interaction is never checked.

Noncompliant code example

assert m.assert_called_once
self.assertTrue(m.has_calls)

Compliant solution

m.assert_called_once()
m.assert_has_calls([call(1)])
