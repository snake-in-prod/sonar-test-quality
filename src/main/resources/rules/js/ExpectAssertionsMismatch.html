expect.assertions(n) with a count that differs from the expect assertions the test makes.

Why is this an issue?

The count exists to catch assertions that never run, typically in a .then or catch. When it is wrong, the test fails for the count rather than for the behaviour, or a later fix of the count hides the assertion that was really skipped. The rule only reports when the count is certain: no loops, branches, assertion helpers or callbacks that may run several times.

Noncompliant code example

it('rejects unknown users', async () => {
  expect.assertions(2);
  await expect(fetchUser(-1)).rejects.toThrow('not found');
});

Compliant solution

it('rejects unknown users', async () => {
  expect.assertions(1);
  await expect(fetchUser(-1)).rejects.toThrow('not found');
});
