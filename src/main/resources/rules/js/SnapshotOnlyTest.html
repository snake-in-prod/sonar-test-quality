A test whose only assertions are file snapshots (toMatchSnapshot, toMatchFileSnapshot) accepts whatever was recorded the first time it ran.

Why is this an issue?

Snapshots are written, not reviewed: a wrong output recorded once becomes the expected value, and large snapshots are often updated with -u without reading them. An explicit assertion on the values that matter states what the test is about. Inline snapshots, error snapshots and tests that also use throwing queries (getBy, findBy) or assertion helpers are not reported.

Noncompliant code example

it('renders the card', () => {
  const { container } = render(<Card title="Hello" />);
  expect(container).toMatchSnapshot();
});

Compliant solution

it('renders the card', () => {
  const { container } = render(<Card title="Hello" />);
  expect(screen.getByRole('heading')).toHaveTextContent('Hello');
  expect(container).toMatchSnapshot();
});
