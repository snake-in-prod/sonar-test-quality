A fixed wait in a test: page.waitForTimeout, cy.wait(<number>), an awaited promise around setTimeout or a sleep helper.

Why is this an issue?

A fixed delay is too long on a fast machine, which makes the suite slow, and too short on a busy CI agent, which makes the test flaky. Waiting for the element, the response or the state the test needs is both faster and reliable.

A wait followed by a check that nothing changed is not reported: the same assertion as before the wait, or a synchronous .not, call count, length or number check. Absence can only be checked after a fixed window.

Noncompliant code example

await page.click('#pay');
await page.waitForTimeout(3000); // Noncompliant

Compliant solution

await page.click('#pay');
await expect(page.getByText('Paid')).toBeVisible();
